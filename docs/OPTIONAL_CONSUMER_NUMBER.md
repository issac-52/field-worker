# 수용가번호 미등록 자료 — 신규 등록 전용 주소 기준

갱신: 2026-11-11. 사용자가 주소 기준은 **기존 자료 보완이 아니라 신규 등록**에만 적용하고, 이미 등록된 주소인데 업로드 행에 수용가번호가 없으면 오류로 처리하도록 명확히 했다.

## 신규 등록

- PK는 자동 생성 내부 `worksites.id`다. 사진·검침·이력·문서의 연결 방식은 유지한다.
- 수용가번호가 있는 행은 기존 수용가번호 기준으로 처리한다. 기존 번호는 ALREADY_EXISTS, 파일 내 번호 중복은 최초 행 우선/DUPLICATE_IN_FILE이며 기존 자료를 덮어쓰지 않는다.
- 수용가번호가 없으면 새주소(E열)가 필요하며 이름(D열)은 없어도 된다. 번호는 SQL NULL로 저장한다.
- 번호 없는 행의 새주소가 **DB의 어떤 수용가 주소와도 겹치지 않을 때만** 등록한다. 기존 수용가의 번호 유무나 이름이 같은지는 관계없다.
- 이미 등록된 주소, 또는 같은 파일에서 앞서 실제 등록 대상으로 채택된 주소면 `DUPLICATE_ADDRESS_WITHOUT_NUMBER` 오류로 해당 행을 제외한다. 기존 수용가를 찾아 보완·수정·병합하지 않는다.
- 번호도 없고 주소도 없으면 `MISSING_ADDRESS` 오류로 제외한다.
- 오류는 invalid와 제외 행에 보고하며 다른 유효 행은 계속 등록한다. 번호 없는 주소 충돌은 ALREADY_EXISTS로 숨기지 않는다.
- 주소의 앞뒤 ASCII 공백을 제거하고 연속 공백/탭/개행을 한 칸으로 정리해 비교한다. 원문을 보존하고 대소문자·구두점·약칭은 임의 변환하지 않는다.
- 번호가 있는 서로 다른 수용가는 같은 주소여도 별도로 등록할 수 있다. 기존 번호라서 무시된 입력 행의 주소는 새 주소로 예약하지 않는다.

## 빈 기본정보 보완

**수용가번호로만** 기존 자료를 찾는다. 번호 없는 행은 `CONSUMER_NUMBER_REQUIRED` 오류이며 주소나 이름으로 대상을 찾지 않는다. 번호가 있는 행의 기존 빈 기본정보만 채우는 화이트리스트/원본 우선/사진·검침·좌표 보존 정책은 유지한다.

번호 없는 자료의 주소가 같더라도 재업로드로 자동 보완하지 않는다. 번호가 생기면 관리자가 아래 방법으로 번호를 등록한 뒤 번호를 포함한 파일로 보완할 수 있다.

## 나중에 실제 번호 등록

관리자 상세 화면의 수용가번호 등록 기능은 유지한다.

- ADMIN+CSRF `PATCH /api/admin/sites/{id}/consumer-number`, body `{consumerNumber:"00012"}`.
- 앞뒤 공백을 제거한 1~100자, 선행0 유지. 중복 번호/기존 번호 덮어쓰기는409.
- 내부 ID·사진·검침을 유지하고 변경 이력을 남긴다.
- 등록 후 재업로드/보완 Excel에도 그 번호를 반영한다.

## 숨김 행 삭제는 별도 정책

이번 변경은 삭제 기준을 주소 단독으로 확장하지 않는다. 기존 번호 기반 및 번호 없는 자료의 주소·이름 기반 미리보기/확인/정산 보호를 유지한다. 이름 없는 번호 미등록 행은 기존 자동 삭제 식별 기준을 충족하지 않으므로 대상에서 제외한다. 주소가 같다는 이유로 기존 여러 건을 일괄 삭제하거나 합치지 않는다.

## DB와 동시 업로드

V13만 추가했다. 번호 없는 수용가의 필수 조건에서 이름을 빼고 주소만 요구한다. 기존 V1~V12와 데이터는 수정하지 않는다. 이전 기준으로 주소가 같은 여러 수용가가 있어도 마이그레이션 중 합치거나 삭제하지 않는다. 기존 주소·이름 복합 UNIQUE 인덱스는 기존 자료 호환을 위해 유지한다.

신규 주소 충돌 정책은 등록 서비스에서 집행한다. 등록과 기본정보 보완 업로드는 같은 PostgreSQL 트랜잭션 advisory lock을 사용하며 READ COMMITTED에서 등록된 주소를 확인한다. 관리자 업로드끼리 순서대로 처리해 서로 다른 이름의 동시 업로드도 중복 등록하지 않는다. 일반 목록·지도 조회는 이 업로드 잠금을 사용하지 않는다. 앱의 업로드를 거치지 않는 직접 DB 쓰기는 이 등록 정책의 경로가 아니다.

## 오류 표시

| 사유 | 화면 |
| --- | --- |
| DUPLICATE_ADDRESS_WITHOUT_NUMBER | 수용가번호 없음: 이미 등록된 주소 |
| MISSING_ADDRESS | 주소 누락 (수용가번호 없음) |
| CONSUMER_NUMBER_REQUIRED | 보완 처리에는 수용가번호가 필요합니다. |

이전 문서의 이름 필수·주소/이름 재업로드 보완·수용가번호 없는 재업로드 ALREADY_EXISTS 규칙은 위 정책으로 대체한다.

## 실제 검증 — 2026-11-11

- 신규 동작 테스트4개 중3개가 기존 구현에서 실패하는 것을 확인한 뒤 수정했다. 이름 없는 신규 주소, 기존 번호 있는 주소와의 충돌, 같은 파일의 주소 충돌, 주소 누락, 번호 없는 보완 차단, 서로 다른 이름의 동시 등록, 실제 등록되지 않은 기존 번호 행의 주소를 예약하지 않는 동작을 검증했다.
- V12→V13에서 기존 같은 주소/서로 다른 이름의 자료와 내부ID가 보존되고 이름 없는 주소 등록 및 주소 필수 제약이 적용되는지 독립 스키마에서 확인했다. V1~V12 변경 없음.
- 실제 실행: Java21/PostgreSQL17 `test bootJar`86개 성공(실패/오류/skip0). 프론트 format:check/typecheck/lint/test27개/build 성공.
- 원본 개인정보 Excel 수동 테스트, 운영 DB/AWS/R2 변경·배포는 수행하지 않았다. 가상 XLSX 및 독립 PostgreSQL을 사용했다.
