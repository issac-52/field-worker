# Field Work Manager — 기술 의사결정 및 포트폴리오 로그

> 업데이트: 2026-10-19  |  상태: 개발 초기  |  납기: 2026-11-14
>
> 목적: 면접 및 포트폴리오를 위해 **결정 근거·대안·트레이드오프·실제 해결 과정·검증 결과**를 지속적으로 기록한다.
>
> 표기: **결정**(방향 확정) / **완료**(사용자 확인 또는 실제 실행) / **계획**(미구현) / **보류**(요구사항 대기) / **검증 필요**(확인 전). 구현한 것으로 부풀려 쓰지 않는다.

## 1. 프로젝트 개요

- 배경: 약 20명의 현장 아르바이트 작업자와 관리자가 사용하는 모바일 중심 현장 조사/업무 관리 웹 서비스.
- 업무 흐름: 관리자 엑셀 업로드(약 2,000행, 주소 포함) → 정제·검증 → 주소의 좌표 변환 및 저장 → 지도 마커 표시 → 작업자가 기존 기초 데이터에 현장 상세정보와 사진 4장 추가 → 임시저장/완료 → 변경 이력 및 건당/월별 정산 → 전체/조건별 엑셀 및 지정 한글 문서 형식으로 출력.
- 모바일 우선. PC는 관리자 통계, 보정 및 내보내기 중심.
- 개발비 약 100만 원; 서버는 2027년 초~중반 종료 예정. 운영비를 무료 크레딧·무료 플랜 내에서 최소화.
- 고객 원본 엑셀, 상세 폼, 한글 문서 템플릿은 아직 미수령. 실제 필드와 문서 출력 범위는 미확정.
- 개인정보·업무 데이터의 외부 공개 및 포트폴리오 재사용은 고객 승인 후 진행.

## 2. 현재 사실과 환경 구분

| 영역 | 상태 | 확인 내용 |
|---|---|---|
| EC2 | **완료** | AWS 서울 리전 Ubuntu 서버 생성, SSH 접속 성공. t3.small/디스크 크기 실제 콘솔 재확인 필요 |
| SSH 키 권한 | **완료** | Windows PEM 접근 권한 과다 오류를 `icacls`로 제한한 후 SSH 접속 성공 |
| Docker | **완료** | Docker Engine 및 Compose 설치, `hello-world` 동작 확인(사용자 보고) |
| PostgreSQL | **완료** | Docker Compose 기동, `pg_isready` 및 `psql SELECT version()` 성공(사용자 보고) |
| Spring Boot API | **계획** | 서버/로컬 연결 및 인증 아직 미구현 |
| FE | **계획** | React/Vite 정식 기능·Cloudflare Pages 배포 미완료 |
| R2 | **보유** | 기존 Cloudflare R2 사용 중; 이번 서비스의 권한/버킷 연동은 미구현 |
| Maps 및 Geocoding | **계획** | NAVER Maps API 연동 미완료 |

**주의:** 이전에 생성한 스타터 ZIP은 Maven, Spring Boot 설정과 `docs/decisions.md` 및 개발용 DB 구성의 **초안**이다. 본 문서의 의사결정은 스타터 파일에 자동 반영된 게 아니며, 실제 구현 시 Java/Spring Boot 버전, DB 버전(서버에서 설치한 PostgreSQL 17 vs 스타터의 16), 인증 및 배포 설정을 하나로 정리해야 한다.

## 3. ADR — 기술 의사결정 기록

### ADR-001: 네이티브 앱 대신 React + Vite 모바일 웹
- **상태:** 결정
- **맥락:** 약 20명이 개인 휴대전화로 현장 기록, PC는 관리자 중심. 짧은 납기.
- **선택:** React, TypeScript, Vite; 모바일 우선 반응형 SPA.
- **대안:** React Native/Flutter, Next.js SSR.
- **근거:** 별도 앱 설치·스토어 심사 불필요, SSR/SEO 필요 낮음, 기존 React 역량 재사용, 빠른 구현과 배포.
- **트레이드오프:** 오프라인 작업과 백그라운드 업로드는 별도 설계 필요. 모바일 사진 권한/브라우저 동작 실기기 테스트 필요.
- **검증:** 현장 휴대폰에서 사진 촬영/파일 선택·지도 성능 테스트.

### ADR-002: Java 21 + Spring Boot 모듈러 모놀리스
- **상태:** 결정(빌드 도구/버전 정합성 재확인)
- **맥락:** 인증, 엑셀 변환, 기록 이력, 정산과 문서 생성이 한 시스템에 들어감. 단기 외주, 20명 규모.
- **선택:** Spring Boot 단일 애플리케이션, 도메인별 패키지; Java 21.
- **대안:** Next.js BFF/Supabase 전용, 여러 마이크로서비스.
- **근거:** Spring/Java 경험 활용, 권한·트랜잭션·감사 로그·파일 처리의 명시적 설계, 서비스 규모에 적합.
- **트레이드오프:** 서버 운영 부담 존재; MSA 대비 독립 확장은 제한되나 현재 불필요.
- **검증:** Spring Boot ↔ PostgreSQL 연결, 인증 통합 테스트, 동시 완료 테스트.

### ADR-003: PostgreSQL + Flyway, 초기 단일 EC2 호스팅
- **상태:** 결정 / PostgreSQL 인프라 완료
- **맥락:** 주소/좌표, 사용자, 작업 기록, 정산의 참조 무결성 필요. 운영비 최소화.
- **선택:** PostgreSQL, 마이그레이션은 Flyway, EC2에서 Docker Compose로 실행.
- **대안:** RDS(관리 편하지만 고정비), MongoDB, 별도 DB VM.
- **근거:** 관계형 무결성과 트랜잭션, 필요 시 JSONB로 가변 입력값 수용, 초기 월 비용 절감.
- **트레이드오프:** 앱과 DB가 단일 장애 지점을 공유하며 OS 패치, 백업 및 복구 책임이 개발자에게 있음.
- **검증:** EBS 영속성, 외부 5432 비공개, 자동 백업과 복원 리허설.

### ADR-004: AWS EC2 프리 플랜 크레딧 활용
- **상태:** 결정 / EC2 및 SSH 완료
- **맥락:** AWS Free 플랜, 약 $100 크레딧과 약 100일 잔여로 보고, 2027년 초~중반 서비스 종료 예정.
- **선택:** EC2 하나에 API/DB 구성, 개발하지 않을 때 Stop, 운영 시작 후 24시간 실행.
- **대안:** Oracle Always Free, Railway, AWS Lightsail.
- **근거:** 보유 크레딧 활용, 운영 기간이 짧고 AWS 배포·Linux·보안그룹·Docker 경험을 쌓을 수 있음.
- **트레이드오프:** 무료 기간/크레딧 종료 전에 Paid 전환 또는 철수 필요. EBS와 공인 IPv4는 정지 중에도 별도 요금 가능.
- **검증:** AWS 콘솔에서 Free 플랜 만료일, 크레딧 유효기간·잔여액, 예산 경보와 월 예상 비용 점검.

### ADR-005: Cloudflare Pages 프론트엔드 호스팅
- **상태:** 결정(배포 미완료)
- **맥락:** 브라우저에서 접근 가능한 HTTPS 프론트 URL이 필요, 운영비 최소화.
- **선택:** Cloudflare Pages의 `*.pages.dev` 기본 주소 + Vite 정적 빌드.
- **대안:** Vercel, EC2에서 프론트도 서빙.
- **근거:** 별도 도메인 구매·프론트 서버 관리 불필요, 무료 정적 배포, 기존 Cloudflare 생태계 사용.
- **트레이드오프:** API는 별도 HTTPS 주소가 필요하고 쿠키/CORS 정책을 맞춰야 함.
- **검증:** Pages에서 모바일 HTTPS 접속, SPA 라우팅 새로고침, API 호출 확인.

### ADR-006: Cloudflare R2에 현장 사진 저장
- **상태:** 결정(연동 미구현)
- **맥락:** 약 2,000건 × 사진 4장으로 최대 약 8,000장; 기존 R2 사용 중.
- **선택:** 비공개 버킷/접두사 + 서버에서 단기 presigned URL 발급 → 브라우저 직접 업로드 → DB에는 파일 키와 메타데이터 저장.
- **대안:** EC2 로컬 저장, DB BLOB, Spring Boot 프록시 업로드.
- **근거:** EC2 디스크·네트워크 부담 완화, 저장소 분리, 기존 자원 재사용.
- **트레이드오프:** CORS, 업로드 완료 검증, 고아 파일 정리, 파일 크기/확장자/MIME 검증, 사진 접근 제어 필요.
- **검증:** 실제 모바일 사진 4장 업로드, 비공개 다운로드 권한, 저장용량과 기존 서비스의 무료 할당량 합산 확인.

### ADR-007: 관리자 발급형 작업자 계정
- **상태:** 결정(구현 미완료)
- **맥락:** 소수 알바 중심이며 불특정 사용자 회원가입 필요 없음.
- **선택:** ADMIN/WORKER, 관리자가 계정 발급·비활성화·비밀번호 재설정.
- **대안:** 공개 셀프 회원가입, 소셜 로그인.
- **근거:** 운영 관리와 권한 통제가 간단하고 불필요한 가입·인증 기능을 줄임.
- **트레이드오프:** 계정 발급/초기 비밀번호 전달 절차와 퇴사 처리 필요.
- **검증:** 접근 통제, 비활성화된 계정의 세션 차단, 관리자 API 권한 테스트.

### ADR-008: 세션/쿠키 인증 우선 검토
- **상태:** 검증 필요(최종 미확정)
- **맥락:** 모바일 웹과 PC 관리자, 소수 사용자. 프론트 `pages.dev`와 API 도메인이 다를 수 있음.
- **후보:** Spring Security 세션(HttpOnly/Secure 쿠키), CSRF 및 SameSite/CORS 정책 명시.
- **대안:** JWT Access/Refresh Token.
- **근거:** 세션 폐기·계정 비활성화 제어가 간편하고 불필요한 토큰 갱신 코드를 줄일 수 있음.
- **트레이드오프:** 서로 다른 사이트 간 쿠키와 브라우저 추적방지 제약을 실제로 검증해야 하며, 불안정하면 인증 방식/도메인 배치 재검토.
- **검증:** 실제 Pages ↔ API 간 로그인 유지, 모바일 Safari/Chrome, CSRF·CORS 테스트.

### ADR-009: 엑셀 원본과 현장 입력의 분리
- **상태:** 설계 방향 결정 / 필드 구조 보류
- **선택:** 업로드 배치 및 `work_sites`의 기초 데이터, `work_records`의 현장 입력 및 완료 상태, `work_photos` 별도 저장. 초기 가변 필드는 JSONB 후보.
- **대안:** 모든 입력값을 한 테이블에 혼합, 전 필드 EAV.
- **근거:** 엑셀 재업로드, 현장 수정, 출처 추적, 원본과 입력값의 명확한 구분. 출력 시 두 데이터 결합.
- **트레이드오프:** JSONB에는 일관된 스키마 검증이 필요하며 잦은 필터 조건은 정규 컬럼/인덱스로 승격해야 함.
- **검증:** 실제 엑셀 컬럼, 고유키·중복 주소, 재업로드 업데이트 규칙, 보고서 예시 확인.

### ADR-010: 완료 이력·정산을 별도 모델로
- **상태:** 설계 방향 결정 / 정책 보류
- **선택:** 변경 이벤트/감사 로그 저장, 완료 시각·완료자 보존, 정산 단가는 해당 작업 시점에 스냅샷 저장. 낙관적 잠금과 중복 정산 방지 고려.
- **대안:** 작업자별 현재 완료 건수 × 현재 단가 계산만 사용.
- **근거:** 수정, 취소, 중복 완료가 있어도 지급 근거를 추적할 수 있음.
- **트레이드오프:** 상태 전이와 취소/재완료 규칙이 다소 복잡해짐.
- **검증:** 관리자 검수 여부, 완료 수정권한, 삭제 정책, 지급 확정 시점 확정.

### ADR-011: 출력 기능은 입력 모델 확정 후 개발
- **상태:** 보류
- **선택:** Apache POI 기반 엑셀 입출력 검토; HWPX 템플릿 및 라이브러리는 샘플 문서 확인 후 POC.
- **근거:** 표/이미지/페이지 레이아웃 요구에 따라 자동 생성 난도가 급변함.
- **검증:** 샘플 1건으로 파일 생성·열기·서식·사진 배치 테스트.

## 4. 문제 해결 로그 (실제 발생한 것만)

### ISSUE-001: Windows SSH PEM 파일 권한 오류 — 해결
- **증상:** `Permissions for 'C:\\KEYR.pem' are too open`, `bad permissions`, `Permission denied (publickey)`.
- **원인:** OpenSSH가 다른 사용자에게 읽기 가능한 개인키를 안전하지 않다고 보고 무시함.
- **조치:** Windows `icacls`로 파일 ACL 상속을 제거하고 현재 계정에 최소 읽기 권한만 부여.
- **결과:** SSH 접속 성공(사용자 확인).
- **면접 핵심:** 공개키 인증에서 개인키 접근권한이 왜 중요한지, Linux chmod와 Windows ACL 차이.

## 6. 포트폴리오용 서술 초안 (성과 확정 전)

> 약 20명의 현장 작업자를 대상으로 한 모바일 중심 위치 기반 작업 관리 시스템을 설계하고 있습니다. 엑셀 약 2,000건의 기초 데이터와 주소 기반 지도 표시, 현장 사진·상세 데이터 입력, 변경 감사, 작업자별 정산, 보고서 출력까지 이어지는 업무 흐름을 설계했습니다. React/Vite, Java/Spring Boot, PostgreSQL, AWS EC2, Cloudflare Pages/R2를 선정했으며, 서비스 규모·납기·운영비를 고려해 모듈러 모놀리스 구조를 채택했습니다.
