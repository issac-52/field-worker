# 주요 의사결정·해결 기록

업데이트: 2026-10-23. 중복 작업 일지·폐기된 API 상세·예상 면접 문답을 통합했다. 개발자의 선택과 사용자 확인, 코드 작성, 실제 검증을 구분한다. 현재 구현 상태는 [프로젝트 컨텍스트](PROJECT_CONTEXT.md), 검증 범위는 [검증 기록](FRONTEND_REVIEW.md)가 기준이다.

## 기술 방향

| 결정 | 근거·대안·트레이드오프 | 상태 |
| --- | --- | --- |
| React/Vite 모바일 웹 | 약 20명과 짧은 납기에 설치/스토어 없이 배포. 네이티브 앱보다 오프라인/촬영 제약 확인 필요 | 선택, Mock 구현 |
| Java 21/Spring Boot 3.5.x/Gradle 모듈러 모놀리스 | 개발자 Spring 경험과 명시적인 트랜잭션·권한 학습. 여러 서비스보다 현재 규모에 단순함 | 선택, 백엔드 초기 코드 |
| PostgreSQL 17/Flyway/EC2 Compose | 관계 무결성·비용 관리. RDS보다 직접 백업·복구·패치 책임이 큼 | 선택, 인프라 기동은 사용자 보고 |

| 관리자 발급 계정·서버 세션 우선 | 공개 가입 불필요, 소수 웹 사용자에서 갱신 토큰 복잡성 감소. cross-site 쿠키/CSRF 검증 필요 | 방향, 실제 인증 미구현 |
| 기초정보·현장 입력·감사·정산 분리 | 재업로드 출처, 수정 전후 기록과 과거 단가 보존. 구체 스키마는 개발자 결정 | 방향, Mock에 일부 정책 구현 |

운영 크레딧은 영구 무료로 가정하지 않는다. 2027년 END까지 데이터와 재시작 가능성을 보존해야 하며 비용/종료 정책은 별도 확인한다.

## 2026-10-19 — 실행 구성과 SSH 권한

- Java 21/Spring Boot 3.5.6/Gradle/PostgreSQL 17/Flyway로 방향을 통일했다. Maven·이전 스타터 버전은 현재 기준이 아니다.
- local/prod DB 설정과 외부 비밀번호 주입, 로컬 DB loopback 바인딩, health 외 API 거부를 적용했다.
- Windows PEM 권한 오류를 icacls로 제한해 SSH 접속한 것은 사용자 확인 기록이다. Docker/PostgreSQL 기동도 사용자 보고이며 이번 문서 정리에서 원격 재검증하지 않았다.
- 과거 Wrapper 미포함 설명은 현재와 다르다. 현재 Wrapper가 있으며 Gradle 9.6.0을 지정한다. 백엔드 테스트 성공 기록은 없다.

## 2026-10-21~22 — A/B 검침과 프론트 시연

- 사용자 확인에 따라 START 2026/END 2027을 약 1년 간격의 별도 검침으로 다룬다. 날짜·지침·조사자·적용 단가를 단계별로 보존하고 B−A는 파생 계산한다.
- 공개 가입 대신 관리자 계정 발급, 비활성 후 과거 이력 유지 방향을 정했다. 세션/JWT 중 세션을 우선 검토했으나 실제 도메인·쿠키 검증 전이다.
- 과거 초안의 인증 서비스·관리자 API 작성 완료 주장은 현재 작업 트리 구현을 뜻하지 않는다. 현재 UserRepository만 존재하고 UserService는 비어 있다.
- 첨부 HWP 양식을 확인했다. 원본에는 위치도·원경·시작/종료 근경 칸이 있으나 최종 사진 배치는 아래 최신 결정과 별도 확인이 필요하다.
- 실제 서버 연결 전에 모바일 업무 흐름을 확인하기 위해 MSW 시연을 선택했다. 실인증·영구 저장으로 오해하지 않도록 안내한다.

## 2026-10-23 — 프론트 구조·권한·대량 조회

- App/페이지/업무 입력/hooks/API/Mock/CSS를 분리했다. 중/소블록 필터와 서버 방식 페이지/전체 요약을 공유한다.
- 수용가·조사자 관리·검침 상세는 기본 20건, API 최대 100건. 지도는 현재 목록 페이지로 한정해 응답 크기를 제한한다. 전체 지도 탐색의 제약은 [후속 제안](MAP_QUERY_DESIGN.md)으로 남겼다.
- 작업자는 본인 실적만 보고 금액은 받지 않는다. 관리자는 조사자별 건수/금액을 조회한다. Mock 권한과 운영 권한은 구분한다.
- Node 회귀로 12,050건/603페이지, 블록 조건, 전체 집계·응답 제한·권한을 검증했다. 이는 운영 부하/메모리 측정이 아니다.

## 2026-10-23 — 지도·검침·사진과 실제 오류 보완

- NAVER 동적 SDK 공유 로더에 준비 대기/중복 요청 방지/15초 제한/실패 재시도를 적용했다. 콜백이 먼저 온 경우 준비 상태를 같은 제한 시간 안에서 재확인하도록 보완했다.
- 지도 파괴 이후 마커 해제에서 발생한 SDK 오류는 마커/리스너를 먼저 정리하고 지도 파괴, 중복 정리 방지로 수정했다. 실제 로컬 지도 표시와 필터/선택을 확인했다.
- 현재 위치는 Geolocation을 이용해 메모리에서만 표시한다. 실제 기기 GPS 성공은 미확인이다.
- 검침은 단계/연도/달력/지침/본인 명의/중복 검사, 날짜·지침 정정과 조건부 버전 검사를 제공한다. 사진은 디코딩·축소·Blob URL 정리와 별도 저장을 제공한다. 실제 영구 저장은 없다.
- Windows CRLF와 Prettier LF 충돌을 frontend 전용 .gitattributes로 정리했다.

## 2026-10-23 — 시연/운영 환경 분리

- demo 모드와 3개 명시 플래그, dist-demo를 사용한다. 운영은 dist이며 로컬 환경파일을 읽지 않고 실행 환경변수만 사용한다.
- 역할은 메모리만 사용하며 전환 시 조회 취소·캐시 제거·홈 이동, 새로고침 WORKER 초기화를 적용했다. 역할 헤더는 Mock 전용이다.
- 일반 빌드에 Mock/전환 설정 혼입 시 거부한다. 실제 환경파일은 Git 제외하고 .env.example만 공유한다. 폐기한 .env.admin/dev:admin/.env.production 절차는 제거했다.
- 환경 조합 회귀, 역할 전환과 운영 헤더 제외, 정적 시연/운영 화면을 확인했다. 원격 배포·운영 인증을 검증한 것은 아니다.

## 2026-10-23 — Excel과 UI 피드백 반영

- 선택 블록 전체 페이지로 실제 XLSX를 생성한다. ExcelJS는 지연 로딩하며 사진 이미지는 제외한다. 중복/건수 변경은 검사하지만 같은 건수 안의 변경에 대한 단일 스냅샷은 보장하지 않는다.
- shadcn/ui 방식의 공통 컴포넌트와 Tailwind v4를 도입했다. 기존 CSS/지도에 대한 영향과 동선 변경을 줄이기 위해 preflight는 제외했다. 라우팅·저장 로직을 보존하는 점진 적용을 선택했다.
- 홈 현황은 바로가기 아래로, 사진과 특이사항은 기본정보 다음으로 이동했다. 중복 제목/건수를 숨기고 접근성 이름은 유지했다.
- 수용가는 한 줄·선행 상태 아이콘·범례, 작은 필터 탭, 화살표 페이지 이동으로 정리했다. 조사자별 현황은 한 줄과 활성/비활성 체크박스를 제공한다.
- 시연 목록 점검을 위해 수용가 180건·조사자 27명·검침 174건을 구성했다. Node 기본 시드와 분리하고 브라우저 다음 페이지를 확인했다.
- 기존 ExcelJS 약 940kB 청크 경고가 남는다. 과거 npm audit에서 moderate 2건이 보고됐으며 해결/최신 상태를 이번 문서 정리에서 재검사하지 않았다.

## 2026-10-23 — 위치도 제외·사진 4종·지도 상태 통일

- 위치도 미리보기/저장/재생성/좌표 수정 Mock을 만들었으나, 요청자 피드백으로 기능 전체를 제거했다. 당시 실제 Static/R2/서버 저장은 구현하지 않았고 이용 권한도 승인으로 간주하지 않았다. 폐기된 상세 설계/API 문서는 제거하고 이 변경 이력만 남긴다.
- 원경/START 근경/END 근경에 임시용 TEMPORARY를 추가해 4슬롯으로 확정했다. 임시 사진 필수 완료 조건은 추가하지 않았다. Excel도 최종 35열이다.
- 지도 조회의 START/END 연도 선택을 없애고 수용가와 같은 전체/미처리/시작검침완료/검침완료 필터를 공유한다. 회색/파랑/초록 마커를 사용한다. 실제 입력의 START/END 탭은 유지한다.
- 사진 4종 저장/5개 거부·중복/형식 검증, XLSX 12행·35열 재조회, 지도 상태 마커와 API 회귀를 확인했다.

## 2026-10-23 — HWP 사전 생성·ZIP 방향 합의

- 10,000건 이상을 다운로드 시 전부 생성하는 대안보다, 저장 시 출력 변경 버전 기록 → 백그라운드에서 해당 HWP만 최신화 → 비공개 R2 보관을 선택했다. 저장 응답은 문서 생성을 기다리지 않는다.
- 다운로드는 최신 HWP 준비를 확인한 뒤 R2 객체를 순차 ZIP으로 조립하는 방향이다. 사전 생성으로 대기 시간을 줄이지만 저장 공간·버전·실패 복구와 ZIP 조립 시간은 남는다.
- RAM 약 2GB를 고려해 단일 작업자·한 건 생성·제한된 사진 디코딩·파일 스트림을 제안했다. 구체 제한과 시간/메모리는 미측정이다.
- [HWP_EXPORT_DESIGN.md](HWP_EXPORT_DESIGN.md)에 최신성·실패 처리·검증 순서를 기록했다. 다음은 가상 텍스트/사진을 포함한 한 건 PoC이며 실제 생성/저장 API는 없다.

## 기록 규칙

새 결정은 문제/선택·대안/트레이드오프/구현/실행한 검증을 구분해 추가한다. 측정하지 않은 성능, 과거 초안 코드, 사용자 보고를 실제 운영 성공으로 바꾸지 않는다. 이번 문서 정리는 소스·실행 안내·폐기 문서의 정합성을 정리했으며 기능 코드를 변경하지 않았다.
