# 성능 개선 기록

현재 상태: **개선 전 기준 측정 완료 / 개선 미적용**

현재 기준은 [포트폴리오 문서](PORTFOLIO.md), [측정 방법과 제한](../../PERFORMANCE_BASELINE_2026-11-10.md), [원시 JSON](../../performance/2026-11-10/baseline.json)이다. 기존 결과는 덮어쓰지 않고 개선별 날짜/커밋 디렉터리에 새 결과를 보관한다.

## 비교 규칙

- 같은 환경, PostgreSQL 이미지 버전, JVM/풀 설정, 데이터 분포, 예열·반복 횟수를 유지한다. 변경되면 차이를 먼저 기록한다.
- 단건 응답시간과 작업 전체 시간, 사진 없는 생성기와 사진 포함 작업, 최초 생성과 캐시 재사용을 분리한다.
- 작업은 여러 번 반복한 뒤 분포를 제시한다. 기존 100건 작업 결과는 각 1회 관측값이므로 해당 제한을 유지한다.
- 개선율은 같은 범위에서 `(기준값 - 개선값) / 기준값 × 100`으로 계산한다. 조건이 달라지면 직접 개선율을 계산하지 않는다.
- SQL 감소와 응답시간 감소를 별도로 적는다. 추정 최대 처리량이나 운영 성과로 바꾸어 표현하지 않는다.
- 실행 명령, 커밋, 원시 결과, 회귀 검증을 남긴 뒤 그래프와 포트폴리오 요약을 갱신한다.

## 01. 다음 개선 — 미착수

### 문제와 가설

- 관측: 목록 20건에서 JDBC execute 62회, 100건에서 302회.
- 가설: 목록 전용 조회 또는 일괄 조회로 행별 추가 SQL을 제거하면 DB 왕복이 줄어든다.
- 대안/선택 근거: 작성 예정.

### 구현 기록

- 코드 커밋/PR: 미작성
- 변경 사항: 미적용
- 트레이드오프 및 권한·응답 계약 영향: 검토 예정

### 측정 결과

| 지표 | 기준 | 개선 후 | 비교 조건 |
| --- | --- | --- | --- |
| 목록 20건 SQL/요청 | 62회 | 미측정 | 동일 2만 건 |
| 목록 20건 p50 / p95 | 24.20 / 42.74ms | 미측정 | 예열 3회, 표본 20회 |
| 목록 100건 SQL/요청 | 302회 | 미측정 | 동일 2만 건 |
| 목록 100건 p50 / p95 | 64.09 / 74.92ms | 미측정 | 예열 2회, 표본 10회 |
| 목록 20건, 동시 10 p50 / p95 | 100.67 / 195.96ms | 미측정 | 총 100회, 풀 10개 |

- 실행 환경/명령: 미작성
- 원시 결과/그래프: 미작성
- 회귀 테스트: 미실행
- 운영 검증: 미실행
- 해석과 남은 제한: 측정 후 작성

## 02. 문서 생성 개선 — 미착수

사진 3장씩 있는 100건 최초 생성 48.47초, 동일 조건 재요청 2.03초가 각각 1회 관측됐다. 전체의 약 94%가 생성기 내부였으나 이미지 처리·XML 구성·압축 중 세부 원인은 아직 분리하지 않았다.

후속 기록에는 생성기 세부 프로파일, 전체 작업 경과, 원본 사진 크기, 최대 RSS/GC, 실제 저장소 GET/PUT 및 지연, 큐 대기를 함께 기록한다. 사진 없는 전체 작업도 별도로 측정한다. 병렬화/캐시 변경의 결과는 아직 없다.
