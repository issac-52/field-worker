# 주소 좌표 변환 및 원본 Excel 상세정보

## 변경 내용

- 관리자 지도 화면에서 전체 수용가 중 좌표가 없는 주소를 NAVER Geocoding으로 변환한다. 기존 좌표는 덮어쓰지 않는다.
- 실행 전 시·군·구를 포함한 지역명을 입력한다. 파일의 축약 주소 앞에 붙여 검색하므로 대상 지역이 맞는지 확인한다. 모든 수용가 대상이며 현재 목록 필터로 범위를 제한하지 않는다.
- `POST /api/admin/geocoding`: `{afterId:0, throughId:null, region:"지역명"}`. 서버가 최대 5건 처리 후 `nextId`, `throughId`, `done`, `rows`를 반환한다. 후속 요청은 반환한 커서와 최초 상한을 사용한다.
- 주소가 없거나 결과가 0/여러 개면 제외한다. API 오류/키 누락/할당량 오류는 실행을 중단하며, 앞서 저장한 좌표는 유지한다. 성공한 변경은 기존 `worksite_edits`에 전후값과 실행자를 기록한다.
- 처리 중에는 화면을 유지해야 한다. 중지 버튼은 현재 요청이 완료된 뒤 다음 요청을 중단한다. 서버 백그라운드 작업이 아니다. 다시 시작하면 이미 등록된 좌표는 건너뛰고, 미등록 주소를 다시 시도한다. 공급자 호출 실패 직전 배치에서 일부 저장된 건은 화면 누적 건수에 반영되지 않을 수 있으나 재시도 시 보존된다.
- 지도는 현재 조회 페이지의 최대 20건을 표시한다. 주소로 얻은 좌표는 계량기 실측 좌표가 아니므로 현장 위치를 확인한다.

## EC2 설정

NAVER Cloud Maps Application에서 **Geocoding** 사용 권한을 활성화하고, 서버의 `/opt/field-work/backend.env`에 아래 값을 넣는다.

```dotenv
NAVER_GEOCODING_CLIENT_ID=발급받은_Client_ID
NAVER_GEOCODING_CLIENT_SECRET=발급받은_Client_Secret
```

Client Secret은 서버 전용이다. 프론트의 `VITE_NAVER_MAP_CLIENT_ID`(브라우저 지도 표시)와 목적이 다르며 `VITE_` 변수에 Secret을 넣지 않는다. Geocoding 요청은 API 사용량/요금에 포함된다. 키 자체는 Git이나 로그에 기록하지 않는다.

새 JAR 및 프론트 배포가 필요하다. env 변경 후 `sudo systemctl restart fieldwork`로 적용한다. 외부 호출 대상은 `https://maps.apigw.ntruss.com/map-geocode/v2/geocode`다. 키/네트워크/할당량의 실제 동작은 운영 설정 후 확인해야 한다.

## Excel 누락 진단 및 표시

기존 Import는 이름(D), 주소(E), 계량기번호(G)를 저장하고 원본 셀 전체를 `source_cells`에 보존한다. 이번 변경은 저장된 J/K/L/AX/BC/BD 및 기존 주소를 API와 상세·지도 기본정보에 연결한다. 상세 화면에는 보존된 월별 A/B/C 세 그룹도 START/END와 분리해 표시한다. 기존 자료 재업로드나 DB 초기화가 필요 없다. V1~V7 및 스키마는 변경하지 않았다.

- 구경, 가구수, 상호, 계량기 유무 원문, 기존 검침담당, 정례검침일, 기존 주소를 표시한다.
- 공급 자료의 `하` 및 월별 세 그룹 의미는 미확정이므로 원문/그룹으로 표시하고 다른 업무 필드로 추정 변환하지 않는다.
- 급수구역·봉인 여부는 해당 Excel에 확정된 매핑이 없어 값을 만들어 넣지 않는다.
- 이름이 없으면 `성명 미기재`, 다른 빈 항목은 `미기재`로 표시한다.
- 첨부 원본을 일회성 PostgreSQL에 재등록해 19,795건의 이름·주소·계량기번호를 보존 원본과 전수 비교했다. 불일치 0건, 이름 있는 원본 19,744건, 이름 없는 원본 51건이다. 운영 DB의 동일성은 직접 접속 제한으로 확인하지 못했다.

## 실행 검증

- 상세 필드 누락 재현 테스트 실패를 확인한 뒤 구현했다.
- PostgreSQL 통합 테스트 및 일반 테스트 36개 통과(실패/skip 0). 주소 변환 외부 공급자는 대역으로 검증했다.
- 원본 수동 Import/재업로드/원본 필드 대조 1개 통과. 개인정보 원본은 Git에 포함하지 않았다.
- 프론트 타입 검사·ESLint·Vitest 16개·운영 빌드 통과. 기존 ExcelJS 청크 크기 경고는 남는다.
- Chromium 합성 응답으로 390/1440px에서 관리자 주소 변환 버튼, CSRF, 처리 결과, 상세 필드 및 가로 넘침을 확인했다.
- 제공된 운영 URL은 개발 환경 네트워크 정책으로 차단되어 직접 로그인/상세 조회하지 못했다. 실제 NAVER API 호출과 운영 데이터 좌표 갱신은 실행하지 않았다.
