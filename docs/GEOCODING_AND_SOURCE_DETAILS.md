# 주소 좌표 변환 및 원본 Excel 상세정보

## 변경 내용

- 관리자 지도 화면에서 선택한 중블록·최초 등록일 조건의 수용가 중 좌표가 없는 주소를 NAVER Geocoding으로 변환한다. 기존 좌표는 덮어쓰지 않는다.
- 실행 전 시·군·구를 포함한 지역명을 입력한다. 파일의 축약 주소 앞에 붙여 검색하므로 대상 지역이 맞는지 확인한다. 변환 패널에서 중블록 또는 최초 등록일을 반드시 선택한다. 두 조건을 입력하면 AND로 적용한다. 최초 등록일은 한국 시간 기준이며 보완 업로드 날짜가 아니다. 지도 목록 필터와는 별도다.
- `POST /api/admin/geocoding`: `{afterId:0, throughId:null, region:"지역명", middleBlock:"중블록명", registeredFrom:"2026-11-07", registeredTo:"2026-11-07"}`. 서버가 최대 100건 처리 후 `nextId`, `throughId`, `done`, `rows`를 반환한다. 후속 요청은 반환한 커서와 최초 상한을 사용한다.
- 주소가 없으면 EMPTY_ADDRESS, 검색 결과가 없으면 NO_MATCH(변환 안 됨)로 반환하고 좌표를 비워 둔다. 여러 결과는 NAVER가 반환하는 첫 번째 주소의 좌표를 사용하며 원래 주소 문자열은 바꾸지 않는다. API 오류/키 누락/할당량 오류는 실행을 중단하며, 앞서 저장한 좌표는 유지한다. 성공한 변경은 기존 `worksite_edits`에 전후값과 실행자를 기록한다.
- 공급자 호출은 최대 10개 동시 실행한다. 20초가 경과하면 다음 10개 묶음을 시작하지 않고 현재까지 결과와 커서를 반환하므로 느린 응답에서는 100건 미만일 수 있다. 단일 서버에서 배치가 중첩되면 GEOCODING_BUSY(409)를 반환한다.
- 처리 중에는 화면을 유지해야 한다. 중지 버튼은 현재 요청이 완료된 뒤 다음 요청을 중단한다. 서버 백그라운드 작업이 아니다. 다시 시작하면 이미 등록된 좌표는 건너뛰고, 미등록 주소를 다시 시도한다. 공급자 호출 실패 직전 배치에서 일부 저장된 건은 화면 누적 건수에 반영되지 않을 수 있으나 재시도 시 보존된다.
- 지도는 목록 검색/페이지와 독립적으로 현재 화면 영역을 조회한다. NAVER 확대 수준 16 이상이고 위·경도 범위가 각각 0.05도 이내일 때만 조회하며, 최대 500건을 표시한다. 500건 초과 지역은 일부만 표시하지 않고 더 확대하도록 안내한다. 이동 완료 후 250ms 뒤 조회하고 이전 요청은 취소한다. 주소로 얻은 좌표는 계량기 실측 좌표가 아니므로 현장 위치를 확인한다.

## EC2 설정

NAVER Cloud Maps Application에서 **Geocoding** 사용 권한을 활성화하고, 서버의 `/opt/field-work/backend.env`에 아래 값을 넣는다.

```dotenv
NAVER_GEOCODING_CLIENT_ID=발급받은_Client_ID
NAVER_GEOCODING_CLIENT_SECRET=발급받은_Client_Secret
```

Client Secret은 서버 전용이다. 프론트의 `VITE_NAVER_MAP_CLIENT_ID`(브라우저 지도 표시)와 목적이 다르며 `VITE_` 변수에 Secret을 넣지 않는다. Geocoding 요청은 API 사용량/요금에 포함된다. 키 자체는 Git이나 로그에 기록하지 않는다.

새 JAR 및 프론트 배포가 필요하다. env 변경 후 `sudo systemctl restart fieldwork`로 적용한다. 외부 호출 대상은 `https://maps.apigw.ntruss.com/map-geocode/v2/geocode`다. 키/네트워크/할당량의 실제 동작은 운영 설정 후 확인해야 한다.

## Excel 누락 진단 및 표시

기존 Import는 이름(D), 주소(E), 계량기번호(G)를 저장하고 원본 셀 전체를 `source_cells`에 보존한다. 이번 변경은 저장된 J/K/L/AX/BC/BD 및 기존 주소를 API와 상세·지도 기본정보에 연결한다. 상세 화면에서는 기본정보와 신규 START/END 검침만 표시한다. 기존 자료 재업로드나 DB 초기화가 필요 없다. 기존 V1~V7은 보존하고 월별 자료 제거용 V8을 추가했다.

- 구경, 가구수, 상호, 계량기 유무 원문, 기존 검침담당, 정례검침일, 기존 주소를 표시한다.
- 공급 자료의 `하` 및 월별 세 그룹 의미는 미확정이므로 원문/그룹으로 표시하고 다른 업무 필드로 추정 변환하지 않는다.
- 급수구역·봉인 여부는 해당 Excel에 확정된 매핑이 없어 값을 만들어 넣지 않는다.
- 이름이 없으면 `성명 미기재`, 다른 빈 항목은 `미기재`로 표시한다.
- 첨부 원본을 일회성 PostgreSQL에 재등록해 19,795건의 이름·주소·계량기번호를 보존 원본과 전수 비교했다. 불일치 0건, 이름 있는 원본 19,744건, 이름 없는 원본 51건이다. 운영 DB의 동일성은 직접 접속 제한으로 확인하지 못했다.

## 실행 검증

- 상세 필드 누락 재현 테스트 실패를 확인한 뒤 구현했다.
- PostgreSQL 통합 테스트 및 일반 테스트 36개 통과(실패/skip 0). 주소 변환 외부 공급자는 대역으로 검증했다.
- 원본 수동 Import/재업로드/원본 필드 대조 1개 통과. 개인정보 원본은 Git에 포함하지 않았다.
- 프론트 타입 검사·ESLint·Vitest 16개·운영 빌드 통과. 기존 ExcelJS 청크 크기 경고는 남는다.
- Chromium 합성 응답으로 390/1440px에서 관리자 주소 변환 버튼, CSRF, 처리 결과, 상세 필드 및 가로 넘침을 확인했다.
- 제공된 운영 URL은 개발 환경 네트워크 정책으로 차단되어 직접 로그인/상세 조회하지 못했다. 실제 NAVER API 호출과 운영 데이터 좌표 갱신은 실행하지 않았다.

## 2026-11-07 — 빈 기본정보 보완 업로드

관리자 → 수용가 Excel 등록 → 업로드 방식에서 **기존 수용가의 빈 기본정보 보완**을 선택한다. 일반 등록 모드는 이전과 동일하게 기존 번호를 ALREADY_EXISTS로 제외한다.

`POST /api/admin/imports/repair`는 같은 원본 XLSX 형식의 multipart file을 받으며 ADMIN/CSRF가 필요하다. 수용가번호가 일치하는 기존 행만 처리하고 신규 수용가는 만들지 않는다. 파일 중복은 최초 행만 처리하며 미등록 번호, 번호 누락, 변경 없음, 보완 완료 및 보완 필드 목록을 전체 행별로 반환하고 import_jobs에 저장한다. `GET /api/admin/imports/{jobId}`로 결과를 다시 조회할 수 있다.

보완 범위는 중/소블록, 성명, 새/기존 주소, 계량기번호/유무, 업종, 관리번호와 원본 구경·가구수·하·상호·수전번호·검침담당·정례검침일이다. null/빈 문자열/공백만 있는 값만 채운다. 정규 컬럼이 비어 있고 보존 원본 셀에 값이 있으면 원본을 우선 복원한다. 기존 값, 수용가번호, 좌표, 검침, 사진, 비고, 특이사항, 정산, 원본 월별 자료는 수정하지 않는다. 전후 기본정보는 worksite_edits에 기록한다.

보완은 파일 전체 트랜잭션이며 파일 오류가 발생하면 해당 요청 변경은 롤백한다. 50,000행 제한을 유지한다. 이미 채워진 값은 수정하지 않으므로 잘못된 기존 값을 교정하는 덮어쓰기 기능은 아니다. 원본에도 없는 이름을 만들어 넣지는 않는다. 스키마/Flyway 변경 없음.
