# 대량 지도 조회 계약 제안 (2026-10-23)

상태: **제안 / 백엔드·MSW 미구현**. 현재 시연은 목록과 동일한 페이지 최대 20건만 지도에 표시하며 전체 지도로 표현하지 않는다.

## 제안 계약

`GET /api/site-map?west=...&south=...&east=...&north=...&zoom=...&middleBlockId=...&smallBlockId=...&q=...&status=...`

- west/east는 경도, south/north는 위도다. 서버는 유한한 값, 지리 좌표 범위, west < east와 south < north, 허용 zoom 및 최소/최대 영역을 검증한다. 전세계 영역으로 전체 데이터를 우회 다운로드하지 못하도록 서버 제한을 둔다.
- 블록/검색/진행상태는 목록과 동일한 필터 타입과 의미를 사용한다. 지도 화면에서는 현재 목록 페이지 범위인지 지도 영역 범위인지 명시한다. 서버 세션 권한을 적용하고 금액·사진 본문은 응답에서 제외한다.
- 응답 후보: `mode: markers | clusters`, `items`, `matchedCount`, `returnedCount`, `truncated`, `invalidCoordinateCount`, `bounds`, `zoom`.
- marker 후보: id, managementNo, name, address, latitude, longitude, START/END 진행 여부. 선택하면 기존 단건 API로 상세를 조회한다.
- cluster 후보: clusterId, 중심 좌표, count, 포함 영역. 클릭하면 그 영역으로 확대하고 재조회한다. 1만 건 전체를 클라이언트에 내려받아 클러스터링하지 않는다.

## 요청 및 수량 제한

- 지도 idle 후 250ms 정도 debounce하고 이동 중 이전 요청은 AbortSignal로 취소한다. query key에는 bounds/zoom과 동일 블록/검색/상태 필터를 포함한다. 이전 영역 응답이 최신 영역을 덮어쓰지 않게 한다.
- 서버 응답 상한은 예를 들어 마커/클러스터 합계 500개로 시작하는 제안이다. 낮은 zoom은 서버 집계, 높은 zoom은 제한된 개별 마커를 반환한다. 실제 확대 수준과 제한값은 현장 밀집도·서버 부하 측정 후 결정한다.
- 상한을 넘으면 자동 집계하거나 `truncated=true`와 확대 안내를 반환한다. 임의 500개만 보여주면서 전체 결과라고 표시하지 않는다.
- 빈 범위, 잘못된 좌표, 같은 주소 다수 계량기, 블록 변경, 빠른 이동·응답 역전·권한 오류와 확대별 수량 상한을 통합 테스트한다.

## 대안과 트레이드오프

- 현재 페이지 20건 유지: 구현이 단순하고 목록과 일치하지만 지도 전체 공간 탐색은 제한된다. 이번 시연에서 선택한 방식이다.
- bounds 기반 개별 마커만: 서버 부담은 적으나 밀집 지역에서 수량 제한 안내가 필요하다.
- bounds와 서버 클러스터: 대량 탐색에 유리하지만 집계 쿼리·캐시와 확대 정책이 필요하다. 백엔드 개발자가 실제 요구와 측정 결과를 보고 채택한다.

좌표 변환, 실제 좌표 보정, 클러스터 쿼리나 인프라는 이번 작업에서 구현하지 않았다.
