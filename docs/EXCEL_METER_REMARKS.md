# Excel 계량기 유무와 비고 분리

업로드 파일의 H열(계량기 유무)을 다음 규칙으로 해석한다.

| H열 원본 | 계량기 유무 표시 | 비고(엑셀) |
| --- | --- | --- |
| 완료 | 완료 | 빈 값 |
| 앞뒤 공백이 있는 완료 | 완료 | 빈 값 |
| 미설치 / 위치 확인 필요 등 다른 문구 | 빈 값 | 해당 문구 |
| 완료(추가 확인) | 빈 값 | 완료(추가 확인) |
| 빈 셀 / 공백만 있음 | 빈 값 | 빈 값 |

앞뒤 공백을 제거한 값이 정확히 `완료`인 경우만 해당한다. 빈 값은 화면의 기존 규칙에 따라 미기재로 표시한다. 완료라는 문구가 일부 포함됐다는 이유로 완료로 판단하지 않는다.

## 저장과 표시

원본 `meter_presence_raw` 및 `source_cells.H`를 수정·삭제하지 않는다. 중복 업로드와 빈 기본정보 보완 정책도 유지한다. 조회 모델에서 H값을 계량기 유무와 비고로 나눠 반환하므로 기존 등록 자료도 재업로드 없이 적용된다. 원본 컬럼이 비어 있고 보존된 H셀이 있으면 이를 사용한다. 둘 다 값이 있으면 원본 컬럼을 우선한다.

- 기존 API 이름 `meterPresenceRaw`는 호환을 위해 유지하지만 표시 값은 `완료` 또는 빈 문자열이다.
- `importRemark` 문자열을 추가한다. 상세/목록에서 제공하고 상세 및 지도 기본정보의 `비고 (엑셀)`에 표시한다.
- 호폐·위치불명·적재·기타의 현장 특이사항과 기존 note는 별도다. H열 비고를 이 필드들로 복사하거나 덮어쓰지 않는다.
- START/END 상태·날짜·지침·사진·정산·HWPX 출력은 변경하지 않는다. DB 원본과 문서 스냅샷을 바꾸지 않아 기존 문서 캐시도 그대로다.

## Excel 다운로드

운영 XLSX는 기존 20열 순서를 유지하면서 8번째 헤더를 `계량기 유무`로 명확히 하고 마지막 21번째 열에 `비고`를 추가한다. 이 두 값은 화면과 같은 분류 규칙을 사용한다.

시연 XLSX는 기존 35열 뒤에 계량기 유무/비고를 추가해 37열이다. 식별자·검침·작업비 등 기존 열 위치는 유지한다. 비고에 `=1+1` 같은 문구가 있어도 수식이 아닌 문자열로 기록한다.

## 실제 검증

- 기존 구현에서 PostgreSQL 신규 통합 테스트2개 실패를 확인한 뒤 구현했다.
- 등록 후 완료/그 외 문구/빈 값/앞뒤 공백, DB와 원본 셀 보존, 이전 원본 셀만 있는 데이터, 목록/상세 일치, 보완 업로드, 기존 특이사항·메모 보존, 실제 XLSX 셀/헤더/수식 방지를 검증했다.
- Java21/PostgreSQL17 `test bootJar`: 81개 통과(실패/오류/skip0). 기존 목록 SQL4회 상한 회귀 테스트 포함.
- 프론트 format:check/typecheck/lint/test27개/build 성공. Chromium 합성 API390/1440px에서 상세·지도 계량기 유무/비고 분리, 완료 표시, 호폐 선택 보존 및 가로 넘침/콘솔 예외 없음을 확인했다.
- 원본 개인정보 Excel 및 운영 DB/AWS/R2 변경·배포는 수행하지 않았다. Flyway 추가/수정 및 기존 데이터의 일괄 갱신도 없다.
